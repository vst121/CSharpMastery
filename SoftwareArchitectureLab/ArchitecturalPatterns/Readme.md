# Main questions to respond when selecting an architectural pattern:

1. What problem does this architecture solve?
2. What are its invariants?
3. What are the dependency rules?
4. What are the trade-offs?
5. What happens when the system grows?
6. Where does it fail?
7. When should we NOT use it?
8. How does modern .NET implement it?

# Main measures to compare architectures using the same business problem:

Coupling
Cohesion
Complexity
Testability
Deployment complexity
Runtime performance
Failure isolation
